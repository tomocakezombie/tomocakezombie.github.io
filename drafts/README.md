# drafts

ブログ記事の Markdown 下書きを置く場所です。

- このフォルダの中身は git に載りません（`.gitignore` で `README.md` 以外を無視しています）。
- `_` で始まるファイル（`_template.md` など）と `README.md` は変換されません。

## 公開の手順

1. `_template.md` をコピーして、`drafts/好きな名前.md` を作り、書く
2. `npm run drafts` を実行する（`src/pages/blog/_posts.generated.mjs` が更新される）
3. 開発サーバーで `/blog/` を確認する
4. `_posts.generated.mjs` を commit して push する（`drafts/` は git に載らないので、生成されたこのファイルが公開される内容になる）

記事を直したいときは、`drafts/` の Markdown を直して 2. からやり直します。記事を消したいときは、Markdown を削除して `npm run drafts` を実行します。

## 書き方

### ファイル先頭のメタ情報（必須）

`---` で囲んだ中に `キー: 値` を 1 行ずつ書きます。

| キー | 必須 | 内容 |
|---|---|---|
| `slug` | 必須 | URL に使う名前（小文字の英数字とハイフン）。例: `my-first-site` |
| `title` | 必須 | 記事タイトル |
| `date` | 必須 | `2026-10-07` の形式 |
| `tags` | 任意 | `,` 区切り |
| `description` | 任意 | 一覧に出る概要 |
| `site.name` | 任意 | サイト情報の枠を出すときに書く（これがあると枠が出る） |
| `site.url` `site.role` `site.period` | 任意 | サイトの URL、役割、期間 |
| `site.tech` | 任意 | 使った技術（`,` 区切り） |

### 本文

| 書き方 | 表示 |
|---|---|
| `## 見出し`（`#` の数は不問） | 見出し |
| 普通の文章（空行で区切る） | 段落 |
| `- 項目` の連なり | 箇条書き |
| `![代替テキスト](/assets/img/blog/x.png "図の説明")` | 画像（図の説明は省略可） |
| 1 行だけの `[ラベル](URL)` | リンクのボタン |

### 未対応の記法

次の書き方は変換されず、そのまま文字として出るか、無視されます（実行時に警告が出ます）。

- 文章の途中のリンク（`文章の[ここ](URL)を見て`）
- 太字、コード、番号つきリスト、コードブロック、表
